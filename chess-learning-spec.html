기능 명세서

읽는 대신 직접 두면서 배우는 체험형 체스 학습 프로그램입니다. Java Swing 객체지향 프로그래밍 팀 과제이며, 이 문서는 팀원이 각자 무엇을, 어떤 순서로, 어떤 규칙으로 만들지 정하는 기준 문서입니다.

1개요와 원칙

제약 조건

  • UI는 Java Swing만 사용합니다. 외부 GUI 라이브러리와 외부 체스 엔진은 쓰지 않습니다. 테스트용 JUnit은 예외입니다.
  • 영속 데이터는 전부 txt(UTF-8). DB, JSON 라이브러리, 직렬화(Serializable)는 쓰지 않습니다.
  • 객체지향 과제이므로 상속, 다형성, 캡슐화, 인터페이스가 필요해서 쓰인 구조여야 합니다(5장 적용표).
  • 팀원 6명 이상, GitHub Organization OOP-TeamA, Gradle 빌드.

체험형 학습 원칙 v0.3

모든 기능의 요구사항과 콘텐츠는 아래 세 원칙을 지켜야 합니다. 요구사항 표의 수용 기준에서 P1~P3로 참조합니다.

P1보드 위 행동으로 끝난다읽기만 하는 화면을 만들지 않습니다. 레슨 단계, 퍼즐, 용어 예시 모두 사용자가 직접 수를 두거나 칸을 고르면서 끝납니다.
P2틀려도 막히지 않는다오답에는 이유를 말해주고, 두 번째엔 힌트를, 세 번째엔 정답을 보여준 뒤 진행시킵니다.
P3결과가 다음으로 이어진다완료와 정답률을 기록하고, 홈 화면이 다음 학습을 추천합니다.

오답 1회무엇이 틀렸는지 설명하고 국면을 되돌림
오답 2회정답 기물이나 도착 칸을 강조
오답 3회정답 화살표 표시, 그 수를 두면 진행

레슨, 퍼즐, 용어 “직접 해보기”에 공통 적용합니다. 기보 맞히기 모드만 점수 측정이 목적이므로 한 번 시도 후 바로 정답을 공개합니다.

명시적 제외 범위

  • 온라인/네트워크 대전, 체스 시계, 사운드
  • Stockfish 등 외부 엔진 연동. 과제의 핵심 구현물인 탐색 알고리즘을 대체해버립니다.
  • PGN 변화수(괄호 분기), ; 주석, $n 형식 평가 기호
  • 로그인과 비밀번호. 프로필은 이름만으로 구분합니다.

공통 블록 형식

  • 인코딩 UTF-8(BOM 없음). #으로 시작하는 줄은 주석, 빈 줄은 무시
  • @종류 또는 @종류 아이디 줄이 새 블록을 시작. 첫 @ 이전의 줄은 이름 없는 기본 블록
  • 블록 안은 키=값. 첫 번째 =만 구분자. 값의 앞뒤 공백은 제거
  • 값 안의 줄바꿈은 \n, 역슬래시는 \\
  • 목록 값은 쉼표, 대안 값은 | 구분. 한 블록에서 같은 키가 두 번 나오면 형식 오류

7콘텐츠 작성 가이드 v0.3

콘텐츠가 체험형 원칙을 지키는지는 코드가 아니라 작성 규칙에서 결정됩니다. 콘텐츠 분량(레슨 15개, 용어 50개, 기보 6국, 퍼즐 30개 이상)은 코드와 별개로 수십 시간이 듭니다.

공통

  • 책, 웹사이트, 다른 앱의 문장을 옮기지 않습니다. 사실(규칙, 기보의 수)은 참고하되 문장은 직접 씁니다.
  • FEN을 쓰면 앱의 FEN 붙여넣기(SYS-05) 또는 콘텐츠 로드 테스트로 반드시 확인합니다.
  • [[용어]] 링크는 한 레슨, 한 기보 안에서 첫 등장에만 겁니다.
  • 존댓말 “~합니다/~보세요”로 통일합니다. 단 용어 정의와 해설은 “~한다”체.

레슨 [E]

  • 한 단계에 한 개념. 설명은 두 문장 이내.
  • 모든 단계에 goal이 있어야 합니다. 설명만 있는 단계는 로드 오류로 처리되므로 만들 수 없습니다(P1).
  • fail은 “틀렸습니다”로 끝내지 않습니다. 무엇이 틀렸는지와 다음 시도 방향을 씁니다(P2).
  • 한 레슨은 3~6단계. 마지막 단계는 앞 단계들을 섞은 응용 문제로 합니다.

기보 해설 [F]

  • 수 데이터는 서로 다른 출처 두 곳 이상과 대조합니다. 한 글자 오타가 기보 전체를 불법으로 만듭니다.
  • 해설은 핵심 수 6~12개에만, 수당 1~2문장. 평가 기호는 해설이 붙은 수에만 답니다.
  • 맞히기 모드에서 너무 어려운 수(정답률이 의미 없는 수)에는 해설에 힌트성 문장을 넣지 않습니다. 해설은 정답 공개 후 보입니다.

용어 [F]

  • 정의는 두 문장 이내. 예시 FEN과 강조 칸은 필수(기보 표기 분류 제외).
  • 전술과 엔드게임 분류는 가능한 한 try.*를 넣습니다(GLOS-07).
  • related에는 실제로 존재하는 용어 id만 씁니다. 테스트가 검사합니다.

퍼즐 [E]

  • 메이트 주제가 아닌 퍼즐은 정답이 유일해야 합니다. 다른 수도 똑같이 좋으면 퍼즐로 쓰지 않습니다. 상급 AI로 확인할 수 있습니다.
  • 상대 응수는 최선의 방어 수로 넣습니다.
  • theme은 정해진 목록에서만: 메이트인1, 메이트인2, 백랭크, 포크, 핀, 스큐어, 디스커버드어택, 프로모션. 추가는 E와 합의 후.

15개발 용어

체스 프로그래밍에서 쓰는 말입니다. 체스 규칙 용어는 앱의 용어집이 다룹니다.

FEN
국면 하나를 한 줄로 쓰는 표기. 공백으로 나뉜 6필드: 기물 배치, 차례, 캐슬링 권리, 앙파상 칸, 반수 카운터, 수 번호.
SAN
사람이 읽는 기보 표기(Nf3, exd5, O-O). 출발 칸을 생략하므로 해석하려면 합법 수 목록이 필요합니다.
UCI 표기
출발 칸과 도착 칸을 붙여 쓰는 표기(e2e4, 승진은 e7e8q). 원래는 엔진 통신 프로토콜 이름입니다.
PGN
태그, SAN 수순, 해설로 이뤄진 기보 파일 형식.
ply
한쪽이 한 번 두는 것. 체스의 “1수”(백과 흑 한 번씩)는 2 ply입니다.
의사합법 수
기물 이동 규칙만 지킨 수. 자기 킹이 체크에 남는지는 아직 검사하지 않은 상태.
perft
깊이별로 합법 수 트리의 말단 개수를 세어, 알려진 값과 비교해 수 생성기를 검증하는 방법.
EDT
Swing의 이벤트 디스패치 스레드. 컴포넌트 접근과 그리기가 모두 여기서 일어나므로 오래 걸리는 작업을 두면 창이 멈춥니다.
SwingWorker
무거운 작업을 백그라운드 스레드에서 돌리고 결과를 EDT로 돌려주는 Swing 클래스.
미니맥스
내 차례엔 최대, 상대 차례엔 최소 평가를 고르며 수읽기 트리를 내려가는 탐색.
알파-베타 가지치기
결과에 영향이 없는 가지를 잘라 미니맥스를 빠르게 하는 방법. 좋은 수를 먼저 볼수록 많이 잘립니다.
PST
기물 종류별로 64칸 각각에 가산점을 둔 표. “나이트는 가운데가 좋다” 같은 지식을 숫자로 넣습니다.
MVV-LVA
가장 비싼 기물을 가장 싼 기물로 잡는 수부터 보는 정렬 기준. 알파-베타의 효율을 높입니다.
반복 심화
깊이 1, 2, 3…을 차례로 탐색해 시간이 다 되면 마지막으로 끝난 깊이의 결과를 쓰는 방법.
