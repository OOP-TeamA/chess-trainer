담당자별 파일 흐름

위에서 아래로 병합·연결 순서가 이어집니다. 같은 행의 상자는 병렬로 진행할 수 있습니다. 화살표는 파일을 넘기는 쪽에서 받는 쪽으로 향합니다. 화면이 좁으면 도표를 좌우로 밀어 보세요.

컴파일에 필요한 파일 실제 기능 연결·검증에 필요한 결과물 완료(11/11 main 기준) 전체 파일 분담과 대기 조건 보기 ↓

단계별 구현 파일

Java 경로 · 아래의 core/Move.java는 app/src/main/java/com/oopteama/chess/core/Move.java를 뜻합니다. 폴더 뒤에 파일명을 여럿 적은 곳은 모두 그 폴더에 둡니다.

타입 색상 · 인터페이스 RuleSet.java · 클래스 StandardRules.java · 레코드·열거형은 기본색

콘텐츠·테스트 · data/는 app/src/main/resources/data/입니다. JUnit 테스트는 app/src/test/java/com/oopteama/chess/ 아래의 대응 패키지에 둡니다.

제안 표시 · 세부 화면 이름이나 파일 담당이 명세에 정해져 있지 않은 곳에는 제안을 붙였습니다. 같은 파일이 여러 단계에 나오면 처음 만든 담당자가 그 단계의 기능을 이어서 구현합니다.

대기 조건 읽는 법 · 컴파일은 다른 사람이 만든 타입이 현재 브랜치에 있어야 실제 코드를 빌드할 수 있다는 뜻입니다. 연결은 샘플로 개발하고 실제 기능·데이터가 준비된 뒤 통합할 수 있다는 뜻입니다. 아래 의존은 계획과 인터페이스 명세의 참조 관계를 기준으로 정했습니다.

완료 표시 · 회색은 2026-11-11 main(87ca20e)에 병합되고 그 단계에 적힌 작업까지 끝난 파일입니다. 같은 파일도 단계마다 맡은 일이 달라 단계별로 따로 판단합니다. 예를 들어 Game.java는 02단계에서는 완료지만 04단계의 toPgn()이 남아 04단계에서는 회색이 아닙니다. 담당 칸의 파일이 모두 끝나면 칸 전체가 회색이 되고, 열린 PR에 있는 파일은 병합 전까지 회색으로 바꾸지 않습니다.
